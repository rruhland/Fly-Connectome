# Alternating paddle games with one learner

Start with the sealed post-course Pong checkpoint and the brick-placement checkpoint at the end of chronological practice. Keep the existing camera tracker, role adaptation, interception relation, motor-order posterior, and timing model active. Start a new camera history and empty actuator queue at each serve. The alternative arms receive the same matched physical starts and rewards through the same controller interface. The routine reset delivers an initial camera frame without a game ID, schedule index, layout seed, button map, or delay.

The first frame supplies two possible cues. A visible paddle rail facing two or more rows of small rectangular targets activates the brick rebound model. Two opposed parallel paddle rails activate the carried Pong placement policy. Ambiguous images use centered interception. Lock the decision for the life, so clearing bricks cannot silently switch the score update. This engineered rule depends on the objects in the image and supports only the scene structures tested here. The rule has the same outcome for quarter-turn rotations of each supported layout.

The brick model receives every positive native brick increment in the selected life. The Pong model receives the ordinary terminal outcome on its selected lives. The bridge supplies camera entities, requests, elapsed physics time, and the signed terminal outcome to the common control path. The inherited between-life relation update uses bounded episode reward and duration. The evaluator records own hit notifications for return counts. Brick and Pong placement have separate state, with each receiving only observations selected by the scene rule. No backpropagation runs.

Each course consists of six blocks in the fixed order Pong, Breakout, Pong, Breakout, Pong, Breakout with six new starts per block. Five arena switches provide two re-entries for each game. Pong uses the original .35 opponent and normal buttons and timing. Breakout uses previously unseen held-out layouts and balanced lateral serves. Both games use a 20-second limit. The first course uses ordinary buttons and timing in both games. The conflicting course reverses requests 0 and 2 in Breakout and applies a six-command queue. The observed interference reflects the combined change. The seeds are fixed in the evaluator and the policy has an independent random generator.

- **Shared.** Carry the last confirmed role and one active sensorimotor state directly into each new life. Once a saved role lacks enough image support, online causal probing verifies the new rail.
- **Role recall.** Also remember the most recent causally verified rail for each visible scene type. Before the first request, restore a remembered rail only if the same appearance cue and rail are present in the opening camera. Continue adapting the shared motor and timing state online.
- **Isolated.** Run the same learner as the shared arm, separately on the chronological Pong subsequence and Breakout subsequence. Both copies start from the same checkpoints as the shared arm, then receive the same starts as their game in the mixed course.

Report the first life and first five actual incoming opportunities for every block. Retain misses and record timeouts or natural serve wins. Report all first and later returns, frames to the first return and the first two-return rally, and the delay and motor-order estimates at entry and exit. Count Pong wins after an own return and Breakout bricks removed after an own return. Present bricks per life and scored second. Since returns can change the rest of the rally, retain the live opportunity denominators. The first-matching belief metrics describe the first frame with the correct active actuator hypothesis and an initialized visual motion model. An already-correct prior can qualify quickly even with little new evidence. Later changes can reverse those early hypotheses.

The evaluator saves before and after learner hashes, initial camera and public feedback hashes, the complete requested-action sequence and native contact geometry. Compare paired starts for byte-identical initial frames and matched pre-contact ball state. Verify all within-stream state boundaries and all reward-table isolation checks. The course and re-entry comparisons are descriptive because there are two observed re-entries per game per course, and their successive outcomes share learning history.
