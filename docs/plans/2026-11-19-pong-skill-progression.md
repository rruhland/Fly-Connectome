# Pong skill progression and transfer

Use the November 19 acquired interception controller as the reference. Work on the three milestones in order. Carry actual learned state between stages and report any replaced components. Keep visual evidence, intended actions, requested buttons, and game reward separate in the implementation. The learner can see camera observations, its own requests, and ordinary game feedback. The evaluator owns the intervention and the scoring annotations. All updates are online and use no backpropagation.

1. **Save the next ball after a control change.** Compare new learners with the shorter-probe controller and a matched copy whose action knowledge is frozen. Vary the time and identity of the switch. The primary outcome is the first ball returned after the switch. Also count subsequent returns, elapsed time to useful action, and ordinary performance. Full identification of all three commands is a separate diagnostic. Test the possibility that moving into position earlier can help both a learner and its frozen copy.
2. **Learn when to move.** Hide a delay or change the paddle's response time without changing its initial button assignment. Compare live timing updates with the same previously acquired model frozen on matched starts. Show recovery, performance after ordinary timing returns, and whether the learner retains the control-change skill. A controller that handles a new delay immediately establishes robustness. Attribute learning through the live/frozen comparison.
3. **Learn where to place a shot.** Retain interception and learn the effect of choosing different contact positions from actual game scores. Report wins after an own return separately from unopposed serves. Compare with the acquired interception policy and matched frozen score-learning controls. Test both scoring and reliable returns across the supported conditions. Choose an opponent against which shot placement can affect the result and document the scope.

Breakout is the proposed next environment. Save the motor and interception components with their learned state before seeing Breakout. The first transfer test should compare carried and fresh knowledge under identical observations and starts, count the first few returns, and then measure how quickly the learner gains additional reward from bricks. The tests must account for the changed paddle axis, object relationships, and visual clutter.

## Transfer tests after Pong

First, rotate the paddle axis in Pong. Let the learner discover which object and motion axis respond to its commands from the public camera, then use the existing motion model to intercept the moving object. Include extra static objects so a learner that expects exactly three visible objects cannot pass by counting them. This isolates the role-binding problem before bricks add a new reward.

Second, seal the Pong checkpoint before the first Breakout frame. Compare three controllers on identical untouched Breakout starts: carried knowledge with all updates disabled, carried knowledge with online updates enabled, and a fresh learner with the same update rule. Use independent randomness for the environment and agent. Report the very first return, the first five incoming balls, frames until the first sustained rally, and learning curves with all lost lives included. A paddle whose axis is supplied as a diagnostic takes a separate line in the results. Evidence for rapid transfer requires an advantage over the fresh learner within those first few opportunities.

Third, learn which contacts remove bricks and produce score. Keep the motion/arrival learner intact. Compare a reward-updating shot policy with frozen Pong aiming and ordinary center interception. Report bricks cleared per life and time, plus returns. Use previously unseen brick layouts and altered control timing for confirmation.

Finally, alternate Pong and Breakout without supplying game labels. Measure speed of reacquisition on re-entry, retention on original conditions, and interference when the same button has different effects across games. An unsignalled return to an earlier game is a stronger test of shared knowledge than separate checkpoint loading. Object-centered causal models have shown transfer among Breakout variants; this project's cross-game question additionally requires discovering similar roles from visual data and using them to act on the first few incoming balls. [Kansky et al., ICML 2017](https://proceedings.mlr.press/v70/kansky17a.html)
