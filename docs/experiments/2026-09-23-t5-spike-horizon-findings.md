# Longer windows weaken the single-cell T5 spike forecast

The [fixed horizon audit](2026-09-23-t5-spike-horizon-protocol.md) held the frozen 50 ms opt-in Tm4 circuit, issue samples, eight-tick target-window width, and all weights fixed while moving the future T5 spike window to +8, +16, or +32 neural ticks. None passes the preregistered preflight across the six position/speed cases; see the [machine-readable result](2026-09-23-t5-spike-horizon-results.json).

For preferred motion at one pixel/frame, order-state ROC AUC is **0.617–0.675** at +8 ticks, **0.550–0.602** at +16, and **0.421–0.457** at +32. At two pixels/frame it is **0.519–0.565**, then **0.474–0.488**, then **0.398–0.440**. The 32-tick state is often *inversely* ranked relative to later spikes. The same target cells and forecast issue times were used at every horizon, so this is not a sample-count artifact. Static and blank controls remain in the result, but the AUC alone rules out every tested horizon.

Stop shifting the target window or increasing learning rate/trials for this single-cell order-state objective. The successful T5 direction circuit is a **motion detector**, not yet a future-event representation. The next architecture hypothesis should treat motion as a retinotopic **population sequence**: ask whether a local T5 motion event at one anatomical column has measured downstream routes that can provide a causal cue for a later event at another column. Prior LPi/VS audits already showed feedforward transmission but silent somata and sparse or sign-mismatched predictive arrivals; the next work should use those results rather than repeat them. Predefine a spatially shifted event target and check anatomical route/timing capacity before adding a new local learning rule. Any such work remains opt-in until learning and held-out Pong relevance pass and the user approves an in-place change.
