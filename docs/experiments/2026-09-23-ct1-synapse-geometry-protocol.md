# CT1 contact geometry from the primary MaleCNS synapse graph

The body-level CT1 shadow failed a frozen null-suppression screen, and body-level partner-column overlap was too broad to identify a real local CT1 branch. Query the public `male-cns:v1.0` neuPrint synapse graph for **only** the selected Tm1/Tm9→CT1_L body 10009 and CT1_L→selected T5c/d synapse pairs, with confidence at least 0.5 on both ends. Check that returned pair counts equal the original raw contact table's 32,728 input and 37,186 output contacts before any geometric interpretation. Cache raw returned coordinates under ignored `runs/`, and commit only a compact, reproducible summary.

Use the CT1-side post-synapse coordinate for Tm1/Tm9 input and CT1-side pre-synapse coordinate for T5 output. The official coordinates are 8 nm voxels. For each T5c/d output site, locate the nearest measured Tm1/Tm9 input site in 3D; report its distance, source class, and whether its anatomically assigned input column is the same as or one hex neighbor from the output T5's afferent-inferred column. Report this separately for y=10/y=22 and withheld y=16 fields. As a control, shuffle source **body-to-column labels** with a fixed seed while leaving all synapse points in place, and compare the observed nearest-site column match with 100 shuffles. Keep both the raw nearest-site fraction and the shuffle distribution; no threshold is to be tuned to make a rescue pass.

Euclidean proximity does not prove electrical continuity along CT1's arbor, so this is a geometry audit, not a compartment reconstruction. If counts do not match, if the server cannot return a bounded subset, or if observed alignment is no better than the shuffled control, stop without altering the model. A spatially coherent result would justify a morphology/branch-specific opt-in CT1 revision before discussing in-place architecture.
