# Frozen T5 motion is useful on bars, but four-way dot decoding fails

The [bar protocol](2026-09-23-m1a-motion-front-end-protocol.md) and its explicit [horizontal extension](2026-09-23-m1a-motion-front-end-extension-results.json) ran the pinned, **weight-frozen** connectome-derived network with the 50 ms Tm4 supplement and T5 local order current. The [initial result](2026-09-23-m1a-motion-front-end-results.json) remains separate. The simple vertical OFF T5d-minus-T5c per-cell opponent score classified **8/8** held-out up/down bar trials at y=14/18 and speeds 1/2 using one threshold fixed at y=10/22. Surprisingly, that score also separated left/right at x=18/32/46; it is therefore not itself an unambiguous two-dimensional direction code. T5a/b horizontal contrasts were weak or inconsistent across positions/speeds.

A more informative *offline diagnostic* readout used the four local T5 subtype rates, standardized on eight calibration trials (two per direction), then classified each held-out trial by nearest direction centroid. It got **12/12** four-way bar directions, with **12/12** moving-bar detections and zero matched static false alarms. This readout uses direction labels for calibration and is not a proposed in-network learning rule or evidence of online learning. The engineered event-state centroid control also recovered all 12 held-out bar displacements exactly under a uniform background.

The [same-shape square-dot protocol](2026-09-23-m1a-square-dot-protocol.md) removed the bar-orientation cue. On the [frozen 3×3 dot responses](2026-09-23-m1a-square-dot-results.json), the same four-way diagnostic method reached only **7/12** held-out directions, below its 10/12 screen. Errors were concentrated in vertical cases, especially speed 2. The bar-trained readout classified 8/12 dots but its bar-calibrated motion-energy threshold rejected **all 12** as quiet, showing poor size/shape transfer. A dot-calibrated energy threshold did separate **12/12** moving dots from their matched static controls with zero static false alarms. The event-state centroid control again recovered **12/12** dot displacements exactly. Detailed per-trial predictions, static checks, thresholds, and input hashes are in the [decoder result](2026-09-23-m1a-motion-decode-results.json).

Native T4a–d soma spikes were essentially absent even on bright moving bars/dots. A moving bright object supplies both ON events at its leading edge and OFF events at its trailing edge; T5 firing in that condition does **not** establish an ON-pathway representation. The observed T5 response is a real, spatially transferable OFF motion foothold, but subtype-averaged T5 spikes do not yet meet the size-invariant, four-direction M1A goal. No narrow gain or horizon sweep is warranted from this result.

Next, test object-state estimation and trajectory forecast on actual event-camera Pong as a *diagnostic ceiling*: reconstruct from events, track the ball without supplying simulator coordinates, and compare forecasts against privileged state only during scoring. Compare persistence, constant-velocity, and a small online locally updated transition model, especially near wall/paddle bounces. If this succeeds while T5-derived small-object input remains weak, test an opt-in shared local event-correlation bridge as a motion front end; seek user approval before any in-place architecture promotion.
