# Zero-shot transfer of generic two-stream M1A prediction

**Status:** Registered opt-in decision audit. Freeze the complete generic visual system from the [local reliability result](2026-09-26-local-rank-reliability-findings.md): fast sensory templates/transitions, signed local affinity, and the learned source/rank readout are trained only on the original 64 unlabeled generic streams. The entity files may continue their ordinary local within-episode motion update. No Pong frame, label, reward, object identity, crop, physics parameter, wall, paddle, or ball position enters any training or inference update.

Evaluate raw 32×64 event-camera streams from four existing held-out Pong seeds at one and four environment steps per camera frame, using the same open-loop rendering helper as prior zero-shot audits. Score full-frame signed next-meaningful-event top-8/top-32 recall and top-32 precision for fast-only, entity-only, equal fusion, aligned locally learned reliability, and shuffled-credit reliability. Report active-camera-event counts and autonomous live-file count distributions; Pong state may be inspected **only after inference** to interpret failures, never to select a track or forecast. Add four held-out generic streams corrupted by a fixed 10% event dropout and 0.1% independent false-event rate, feed only the corrupted events, and score against the uncorrupted next event so unpredictable injected noise is not rewarded. Record the same forecast arms and file counts. Do not train on Pong or corrupted test streams, and do not alter weights, rank budget, thresholds, or scene-specific gains in response to results.

**Decision rule:** A production M1A proposal is worth review only if aligned local reliability beats fast-only, entity-only, and shuffled credit on both Pong cadences and retains a clear advantage under generic corruption, while the autonomous file state does not explode in count. Passing forecast scores alone do not excuse false births or crossing identity. If Pong or corruption fails, report the failure as an architectural transfer limit and choose one substantive representation/reliability revision; avoid narrow gain or threshold sweeps.
