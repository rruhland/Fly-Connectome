# Zero-shot camera-rate transfer to Pong scenes

**Status:** Opt-in evaluation only. The learned transition stays frozen after generic moving-pattern training; no Pong object, ball, paddle, wall, collision, or reward information enters it. Pong supplies only event-camera frames and is used as an evaluation environment.

Run four held-out open-loop Pong seeds with the existing 32×64 event camera. Sample once per native physics frame and, as a temporal-density control, once every four physics frames. Use the same local correlation input and saved 24-unit sensory code at both rates. Score one-step latent spatial occupancy on frames where the next actually observed latent code is nonempty, against frozen/shuffled transitions and the previous-code persistence baseline. Report event pixels per frame, fraction of frames with nonzero correlation and latent code, prediction F1, and hidden-state activity on camera-quiet frames. No privileged simulator state is used for training or scoring.

This test distinguishes a learned transition that transfers to natural event timing from a front end starved by subpixel per-frame motion. A useful zero-shot result requires learned F1 to beat persistence by at least 0.10 on active frames at the native rate, with a substantial fraction of frames generating a code. If only the four-frame sampling control works, investigate temporal support in the low-level local input before revising the learned state or promoting production architecture. Do not interpret latent activity on a camera-quiet frame as a false visible event; hidden state and emitted events are separate.
