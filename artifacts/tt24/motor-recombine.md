# Recalling motor knowledge on a physically different arm

We reused an electronic command mapping previously learned on one body when the same mapping was installed on a physically different arm. The bank also encountered one genuinely new mapping per receiving body and later revisited the initial and earlier interfaces. Recognition used only short movements and encoders. The ensuing ball games used the donor-trained visual motor readout with wrist RGB and encoders. [Saved memory](motor-bank-motion.npz) · [Acquisition](motor-sampling.md) · [Runner](../../scripts/experimental/tt24_motor_recombine.py)

The bank recognized all four familiar interfaces on the opposite bodies in 36, 36, 42 and 51 control ticks (0.60–0.85 s). Learning them from scratch took 91, 86, 133 and 163 ticks (1.43–2.72 s). Across the first three fresh drops on each interface the bank earned 175 rebounds, against 146 when relearning, 144 with the true inverses and 12 using the original drive. Each unknown interface was treated as new and later recognized. The direct advantage is the reduced interruption with playable control. Small motor differences can produce large differences in game results. [Stock recipient](motor-recombine-motion-stock.json.gz) · [Altered recipient](motor-recombine-motion-alternate.json.gz)

On a separate set of mappings, the original fixed-timing sampler also recognized all four after 42 ticks but carried larger errors. It scored 74 across the first 12 games, versus 110 relearning and 155 with the true inverses. Each course saved and reloaded the resulting motor banks exactly.
